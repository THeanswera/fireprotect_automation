# Модель безопасности

## Границы данных

`ProjectElement` хранит исходные инженерные значения с единицами и
provenance. `Rx3Input` содержит только допустимые входы RX3. `Rx3Result`
создаётся только из отдельного рассчитанного файла и не используется как
обычный вход следующего расчёта. Нормативное назначение R хранится в
`RequiredFireResistanceDecision`; данные производителя огнезащиты находятся
в отдельном technical registry.

Источник истины определяется типом данных:

- усилия и геометрия: проектный источник или явное решение инженера;
- результат RX3: `calculated.rx38` после отдельной проверки GUI evidence;
- нормативное назначение: `NormativeTrace` и запись нормативного registry;
- толщина и расход: первичная техническая документация производителя;
- Excel и проектная пояснительная записка: только secondary source;
- `PROBABLE` и `UNKNOWN` RX38: исследовательские данные без права записи.

## Fail-closed правила

Ненулевые `Mx`, `My`, `Qx` или `Qy` блокируют RX38, пока их mapping не
получит статус CONFIRMED. Допускается только чистый осевой случай с отдельным
`AXIAL_ONLY` evidence. Допуски задаются `ActionZeroTolerance` через
`Quantity` и `Decimal`; универсального скрытого допуска нет.

Знак N изменяется только через версионированный `LiraRx3ForceConvention`.
Каждый multiplier и исходное/целевое значение попадают в audit. В production
неподтверждённая конвенция блокирует работу.

Марка стали не меняется отдельно от расчётной прочностной характеристики.
Пока семантика RX38 field 33 не доказана, разрешено только legacy numeric
match той же марки; расхождение блокирует генерацию. Проверенная запись field
33 требует отдельного `SteelCalculationProperties` evidence.

Старые fields 44 и 54 физически сохраняются для совместимости шаблона, но
имеют статус `STALE_TEMPLATE_RESULT`, исключены из `Rx3Input` и не могут быть
приняты до доказанного пересчёта. Byte-identical calculated/generated означает
`RX3_RECALCULATION_NOT_PROVEN`.

## Режимы

- `DRAFT`: исследование; выпуск всегда запрещён.
- `VALIDATION`: controlled experiments с явно перечисленными исключениями;
  выпуск всегда запрещён.
- `PRODUCTION`: любое отсутствующее критическое доказательство является
  blocker, а не warning.

`evaluate_issue_readiness` выдаёт `READY_FOR_ISSUE` только для production и
только при пустом списке blockers. Warning никогда не снимает blocker.

## Предел доказательств

Открытие файла в RX3 доказывает только читаемость. Успешный pytest доказывает
поведение реализованных контрактов, но не нормативную корректность формулы или
актуальность документа. Формула Excel воспроизводит исследованную книгу, но не
становится от этого нормативным или техническим первичным источником.
