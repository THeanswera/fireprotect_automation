## 2. Словарь терминов

### Программы

**ЛИРА-САПР** — программа для расчёта строительных конструкций методом
конечных элементов. В ней строится расчётная модель: узлы, стержни, нагрузки.
Результат расчёта — усилия в стержнях.

**RX3** — программа расчёта огнестойкости стальных конструкций. По заданному
сечению, нагрузке и схеме обогрева она считает критическую температуру стали,
коэффициент снижения прочности и время до потери несущей способности. Именно
она даёт ответ «конструкция выдержит R90 или нет».

**FireProtect Automation** — наш собственный программный комплекс. Он связывает
ЛИРА-САПР и RX3, считает геометрию, подбирает огнезащиту и заполняет документы.
Исходный код лежит в папке `D:\ОГЗ`.

**Microsoft Excel** — электронные таблицы. В проекте используется конкретная
рабочая книга `01_Общая ОБМ — копия.xlsx`.

**PowerShell** — программа командной строки Windows. Через неё запускаются
команды нашего комплекса. Как её открыть — см. раздел 11.

### Файлы и форматы

**.lir** — файл проекта ЛИРА-САПР. Внутренний закрытый (бинарный) формат
программы. Человеком не читается, нашей программой не разбирается и разбираться
не будет: восстановление смысла закрытого формата запрещено правилами проекта.

**.xlsx** — файл Excel. Из него мы читаем выгрузки из ЛИРА-САПР.

**.rx38** — файл проекта RX3. Это текстовый файл, состоящий из записей по
200 полей каждая. Одна запись — одна конструкция.

**.rxdb** — база данных сечений и материалов RX3. Из неё мы берём геометрию
профилей.

### Инженерные термины

**Профиль (сечение)** — форма и размеры поперечного сечения стержня. Например
«Двутавр 30К1» или «Швеллер 22П».

**Марка** — обозначение конструкции на чертежах. Например «К1» — колонна,
«Б1» — балка, «Св1» — связь.

**ПТМ (приведённая толщина металла)** — отношение площади поперечного сечения
к обогреваемому (прогреваемому) периметру. Измеряется в миллиметрах. Основной
параметр для подбора толщины огнезащиты: чем массивнее металл, тем медленнее он
нагревается.

**Обогреваемый периметр** — часть периметра сечения, к которой подводится тепло
при пожаре. Зависит от числа сторон обогрева.

**Число сторон обогрева** — сколько сторон конструкции открыты огневому
воздействию. Бывает 4 стороны (отдельно стоящая колонна), 3 стороны (балка,
примыкающая к перекрытию), 2 стороны и другие схемы.

**R (предел огнестойкости)** — время в минутах, в течение которого конструкция
сохраняет несущую способность при пожаре. Обозначается R15, R45, R60, R90,
R120. Требуемое значение задаётся нормами и проектом.

**ОБМ** — огнезащитный материал (в вашем проекте — система «ОБМ-Мет»).

**Толщина огнезащиты** — толщина слоя огнезащитного состава в миллиметрах,
которую нужно нанести, чтобы получить требуемый предел огнестойкости.

**Расход** — количество огнезащитного состава на один квадратный метр
обрабатываемой поверхности.

**Огнестойкость** — способность конструкции сопротивляться пожару.

**Огнезащита** — меры, повышающие огнестойкость (нанесение состава,
облицовка).

### Термины нашего комплекса

**Выгрузка** — файл Excel, сохранённый из ЛИРА-САПР с таблицей результатов.

**Набор (bundle)** — папка с результатами одной операции: исходные данные,
промежуточные файлы, отчёты. Каждый набор создаётся заново и никогда не
перезаписывает предыдущий.

**Соответствие колонок (mapping)** — файл, в котором написано, какая колонка в
вашей выгрузке что означает. Нужен потому, что разные версии ЛИРА называют
колонки по-разному.

**Происхождение (provenance)** — запись о том, откуда взято каждое число: файл,
лист, строка, ячейка, исходный текст, единица измерения. Без происхождения
число не считается доказанным.

**Кандидат (candidate)** — строка из выгрузки, которая может оказаться
расчётной, но это ещё не доказано.

**Расчётная (governing)** — та строка усилий, которая определяет работу
конструкции: максимальное усилие из нужного сочетания. Выбор расчётной строки —
**инженерное решение**, программа его за вас не принимает.

**Готовность к выпуску (IssueReadiness)** — итоговый статус. Сейчас он
`NOT_READY_FOR_ISSUE`, то есть выпускать документацию автоматически нельзя.

## 5. ЗАДАЧА 1. Четыре выгрузки из ЛИРА-САПР

### Что это

Из ЛИРА-САПР нужно сохранить **четыре** таблицы в формате Excel. Все четыре
обязательны, потому что каждая содержит свою часть сведений.

### Куда сохранять

Создайте папку для проекта, например `D:\ОГЗ\Примеры\`. Сохраняйте файлы с
понятными именами по образцу:

```text
<Название проекта>_усилия.xlsx
<Название проекта>_элементы.xlsx
<Название проекта>_жесткости.xlsx
<Название проекта>_узлы.xlsx
```

Образец уже есть в проекте — четыре файла «Мед центр Васька 2».

### Таблица 1. Усилия

**Название таблицы в ЛИРА:** «Таблица усилий (стержни)»

**Файл:** `<проект>_усилия.xlsx`

**Что должно быть внутри:**

| Колонка | Что означает |
|---|---|
| `№ элем` | номер элемента (стержня) |
| `№ сечен` | номер расчётного сечения внутри элемента (1, 2, ...) |
| `N (т)` | продольная сила в тоннах-силах |
| `Mk (т*м)` | крутящий момент |
| `My (т*м)` | изгибающий момент относительно оси Y |
| `Mz (т*м)` | изгибающий момент относительно оси Z |
| `Qy (т)` | поперечная сила по оси Y |
| `Qz (т)` | поперечная сила по оси Z |
| `Ry (т/м)` | реакция по оси Y |
| `Rz (т/м)` | реакция по оси Z |
| `Тип элем` | тип элемента |
| `№ загруж` | номер загружения |
| `Составл` | составление (признак сочетания) |

**Важно:** колонка `Составл` в имеющейся выгрузке заполнена прочерками, а
`№ загруж` равен единице во всех строках. Это значит, что выгружено **одно**
загружение, а не расчётные сочетания. Для подбора огнезащиты это пока
допустимо, но для полноценного автоматического выбора расчётной строки нужна
выгрузка по сочетаниям (РСУ/РСН). Про это отдельный пункт ниже.

### Таблица 2. Элементы

**Название таблицы в ЛИРА:** «Таблица элементов»

**Файл:** `<проект>_элементы.xlsx`

**Что должно быть внутри:**

| Колонка | Что означает |
|---|---|
| `№ элем` | номер элемента |
| `Тип элем` | тип элемента (10 — стержень) |
| `Кол.сечений` | сколько расчётных сечений у элемента |
| `Тип жестк` | номер типа жёсткости — **ключ к профилю** |
| `Угол м.осей` | угол поворота местных осей, градусы |
| `AX н`, `AX к` | жёсткие вставки в начале и конце |
| `№№ узлов` | номера узлов начала и конца элемента |

Эта таблица связывает элемент с типом жёсткости, а через него — с профилем.
Она же даёт угол поворота осей и номера узлов.

### Таблица 3. Жёсткости

**Название таблицы в ЛИРА:** «Таблица жёсткостей»

**Файл:** `<проект>_жесткости.xlsx`

**Что должно быть внутри:**

| Колонка | Что означает |
|---|---|
| `Тип жесткости` | номер типа жёсткости |
| `Имя` | название профиля и марки в скобках |
| `Параметры` | жёсткостные характеристики |

**Это самая важная таблица.** Именно из неё берётся профиль и марка. Пример из
вашего проекта:

```text
Тип жесткости 1  ->  Двутавр 30К1 (К1)
Тип жесткости 2  ->  Двутавр 20К1 (К2)
Тип жесткости 11 ->  Двутавр 60Б1 (Б1)
Тип жесткости 12 ->  Швеллер 22П (Б2)
Тип жесткости 13 ->  Уголок параллельно полкам 80 x 6 (Сг1)
Тип жесткости 5  ->  Профиль "Молодечно" 120 x 6 (К5)
```

Формат имени: **сначала профиль, потом в круглых скобках марка**. Марка «Б2» —
это та самая марка, которая уже проверялась в контрольном расчёте RX3.

### Таблица 4. Узлы

**Название таблицы в ЛИРА:** «Таблица узлов»

**Файл:** `<проект>_узлы.xlsx`

**Что должно быть внутри:**

| Колонка | Что означает |
|---|---|
| `№ узла` | номер узла |
| `X (м)`, `Y (м)`, `Z (м)` | координаты узла в метрах |
| `X`, `Y`, `Z` | признаки связей по поступательным перемещениям |
| `UX`, `UY`, `UZ` | признаки связей по поворотам |

По координатам узлов вычисляется **длина** каждого элемента: расстояние между
узлом начала и узлом конца. Признаки связей показывают закрепления.

### Как проверить, что выгрузка удалась

Откройте файл в Excel и убедитесь, что:

1. Первая строка — название таблицы (например «Таблица усилий (стержни)»).
2. Строка с заголовками колонок — **третья**.
3. Есть строка с данными (не пустая).

Не переименовывайте листы и не удаляйте первые строки: программа ищет
заголовки именно в третьей строке.

### Про сочетания (РСУ/РСН)

**РСУ** — расчётные сочетания усилий. **РСН** — расчётные сочетания нагрузок.
Это таблицы, где ЛИРА-САПР сама сводит загружения в невыгодные комбинации.

Сейчас у вас выгружено только одно загружение. Чтобы автоматика могла
подбирать расчётную строку, нужна выгрузка «Таблица усилий (стержни)» по
сочетаниям, где колонка `Составл` заполнена, а `№ загруж` содержит номера
сочетаний.

**Что сделать:** повторите выгрузку таблицы усилий, выбрав расчёт по РСУ (или
РСН), и сохраните отдельным файлом `<проект>_усилия_РСУ.xlsx`.

Если такой режим в вашей версии ЛИРА называется иначе — напишите, как именно,
и я внесу это в инструкцию.

## 6. ЗАДАЧА 2. Выбор стандарта на двутавры

### В чём проблема

В вашей таблице жёсткостей записан профиль **«Двутавр 30К1»**. При попытке
получить его геометрию из базы сечений RX3 программа нашла **два разных
профиля с одинаковым обозначением**:

| Стандарт | Обозначение | Высота, мм | Ширина, мм | Стенка, мм | Полка, мм | Площадь, см² |
|---|---|---|---|---|---|---|
| ГОСТ 26020-83 | `30К1` | 296 | 300 | 9 | 13,5 | 108 |
| СТО АСЧМ 20-93 | `30 К1` | 298 | 300 | — | — | 110,8 |

Площадь сечения различается: **108 против 110,8 см²**, то есть примерно на
2,5 %. Площадь входит в ПТМ, ПТМ влияет на толщину огнезащиты. Ошибка в
стандарте может дать другую толщину.

Такая же неоднозначность есть у `20К1`, `30Б2`, `45Б1` и других двутавров.

### Почему программа не выбирает сама

Правила проекта запрещают угадывать. Два разных стандарта дают разные числа,
и выбрать между ними может только инженер.

### Что от вас нужно

Ответ по каждому типу двутавра, например:

```text
30К1  -> ГОСТ 26020-83
30Б2  -> ГОСТ 26020-83
45Б1  -> ГОСТ 26020-83
60Б1  -> ГОСТ 26020-83
```

**Подсказка (не доказательство):** в вашей выгрузке обозначение записано без
пробела — «30К1», а не «30 К1». Стиль без пробела соответствует ГОСТ 26020-83.
Но подтвердить это должны вы, поскольку от этого зависят расчётные значения.

Если в проекте используются профили по СТО АСЧМ 20-93 — так и напишите.

## 7. ЗАДАЧА 3. Документы на огнезащитный материал

### В чём проблема

В книге Excel есть два справочных листа: **«Толщина ОЗ»** и
**«Расход ОЗ»**. По ним программа подбирает толщину и расход. Но **источник
этих таблиц в самой книге не указан**.

В рабочей папке есть пояснительная записка `021_ПЗ_Огнезащита.docx`, где
названы:

- система **«ОБМ-Мет»**;
- базальтовый материал **«ОБМ-Ф»**;
- клеевой состав **«EXPERT Standart»**.

Но пояснительная записка — это **вторичный** документ, а не документ
производителя. Кроме того, в одной книге встречаются три разных названия:
«ОБМ», «Expert» и `DEFENDER M solvent`, и неясно, один это материал или разные.

### Обнаруженное расхождение

| Источник | ПТМ от 3,4 до 11,0 при R90 |
|---|---|
| Пояснительная записка | 10 мм |
| Книга Excel | 8 мм |

Разница — 2 мм. Программа **не будет** выбирать правильное значение
автоматически, пока нет документа-основания.

### Что от вас нужно

Любые из перечисленных документов, в виде файла:

1. **ТУ** — технические условия на материал.
2. **Протокол огневых испытаний** — документ испытательной лаборатории.
3. **Сертификат соответствия** — с номером и сроком действия.
4. **Технологический регламент** производителя.
5. **Техническая документация**, где приведены таблицы «ПТМ — R — толщина» и
   «расход на м²».

Также нужен ответ: **«ОБМ», «Expert» и `DEFENDER M solvent` — это один
материал или разные?** И если разные — какой применяется в проекте.

### Что будет, когда документы появятся

Каждому материалу заводится карточка с полями: производитель, сертификат, ТУ,
тип огнезащиты, диапазон ПТМ, предел огнестойкости R, толщина, расход,
плотность, потери, грунтовка, условия эксплуатации. После этого подбор

Файл для заполнения уже есть: `technical/fireproofing_registry.yaml`. Сейчас

## 8. ЗАДАЧА 4. Инженерные значения

### 8.1. Требуемый предел огнестойкости

По каждой конструкции нужно указать требуемый предел огнестойкости R и
обоснование (документ, пункт, редакция).

Пример:

```text
Колонны К1-К4     R90
Балки Б1-Б4       R60
Связи Св1-Св4     R90
```

В книге Excel это колонка **X** («Требуемая огнестойкость, мин»). Сейчас она
заполнена значением 90 для строк.

### 8.2. Число сторон обогрева

По каждой конструкции нужно указать, сколько сторон открыто огневому
воздействию. От этого зависит обогреваемый периметр, а значит ПТМ.

Пример:

```text
Колонны  - 4 стороны
Балки    - 3 стороны (сверху перекрытие)
Связи    - 4 стороны
```

Если у разных конструкций по-разному — перечислите по маркам.

### 8.3. Коэффициенты запаса 1,2 в книге Excel

В книге есть три коэффициента 1,2 подряд. Я их расшифровал по формулам:

| Ячейка | Формула | Подпись рядом | Что делает |
|---|---|---|---|
| `AC51` | `=AC50*1,2` | «Узлы» | увеличивает площадь на 20 % |
| `AG51` | `=AG50*1,2` | «Потери» | увеличивает расход на 20 % |
| `AC52` | `=AC51*1,2` | «Грунт», «Маты» | увеличивает ещё на 20 % |

Кроме них есть две введённые вручную цифры:

| Ячейка | Значение | Подпись |
|---|---|---|
| `AC54` | 1523 | «5 мм» |
| `AC55` | 614 | «8 мм» |

**Проблема:** подписи есть, но **обоснования этих 20 % в книге нет**. Это
внутренняя практика, а не норматив.

**Что от вас нужно:** подтвердить, что эти коэффициенты нужно применять, и
указать основание (например: «принято по опыту организации», «по ТУ
производителя, пункт такой-то»). Либо указать другие значения.

Без вашего решения программа оставит эти ячейки как есть и не будет
формировать итоговую спецификацию автоматически.

## 9. ЗАДАЧА 5. Контрольный расчёт в RX3

### Зачем

Контрольный расчёт — это независимая проверка. Пока в RX3 вручную не выполнен
хотя бы один полный цикл, мы не можем утверждать, что подготовленный файл
корректен. Это требование правил проекта.

### Порядок действий

1. Откройте подготовленный шаблон `template.rx38`. Запишите все значения на
   экране и сделайте снимок экрана.
2. Откройте подготовленный файл `generated.rx38`. Сверьте с шаблоном:
   - марку;
   - профиль;
   - марку стали;
   - продольную силу N;
   - все четыре компонента (Mx, My, Qx, Qy) — должны быть нулевыми, если это
     осевой случай;
   - длину;
   - закрепление;
   - расчётную длину;
   - режим огневого воздействия;
   - требуемый предел R;
   - режим расчёта критической температуры.
3. **При любом расхождении — остановитесь** и сообщите мне. Не продолжайте.
4. Нажмите кнопку **«Рассчитать»**. Дождитесь сообщения о расчёте. Это ещё не
   значит, что главная таблица обновилась.
5. Нажмите кнопку **«Сохранить в таблицу»**. Теперь таблица обновлена.
6. Выполните **«Сохранить как»** в **новый** файл `calculated.rx38`. Никогда не
   сохраняйте поверх исходного.
7. Передайте мне файл `calculated.rx38` и снимки экрана.

### Что важно не делать

- Не запускайте ЛИРА, RX3 и Excel автоматически «на всякий случай».
- Не изменяйте исходные файлы шаблонов.
- Не переименовывайте файлы после сохранения.

## 11. Как запускать команды на Windows

### Как открыть PowerShell

1. Нажмите клавишу **Windows**.
2. Наберите `PowerShell`.
3. Нажмите **Enter**.

Откроется чёрное или синее окно с приглашением вида `PS C:\Users\...>`.

### Как перейти в папку проекта

Скопируйте строку целиком, вставьте в окно и нажмите Enter:

```powershell
cd D:\ОГЗ
```

`cd` — команда перехода в папку.

### Как проверить, что всё готово

```powershell
python -m fireprotect.cli --help
```

Должен появиться список команд. Если появилась ошибка — см. раздел 12.

**Проверено:** команда работает из любой папки, потому что комплекс
установлен в систему. Но для порядка рекомендуем всегда переходить в `D:\ОГЗ`.

### Первая команда: разобрать выгрузку

```powershell
python -m fireprotect.cli prepare-lira-review `
  --input "Примеры\Мед центр Васька 2_усилия.xlsx" `
  --mapping "mappings\lira_forces.json" `
  --output-dir "runs\медцентр_усилия"
```

Разбор по частям:

- `python` — запустить Python;
- `-m fireprotect.cli` — запустить наш комплекс;
- `prepare-lira-review` — название операции: «подготовить просмотр выгрузки
  ЛИРА»;
- `--input "..."` — файл выгрузки, который вы сохранили из ЛИРА;
- `--mapping "..."` — файл соответствия колонок (готовый файл уже лежит в
  папке `mappings`);
- `--output-dir "..."` — **новая** папка, куда положить результат. Она должна
  ещё не существовать, иначе команда откажется работать (это защита от
  случайной перезаписи);
- обратная кавычка `` ` `` в конце строки означает «продолжение команды на
  следующей строке». Если она мешает — напишите команду одной строкой.

### Вторая команда: перечислить кандидатов

```powershell
python -m fireprotect.cli prepare-lira-selection `
  --forces "runs\медцентр_усилия\forces.json" `
  --output-dir "runs\медцентр_кандидаты"
```

Результат — таблица `candidates.csv`, которую можно открыть в Excel.

### Третья команда: проверить ваш выбор расчётной строки

Сначала откройте `selection_template.json`, заполните поля `declared_by`
(кто выбрал), `basis` (на каком основании) и `candidate_id` для каждого
элемента. Затем:

```powershell
python -m fireprotect.cli validate-lira-selection `
  --candidates "runs\медцентр_кандидаты\candidates.json" `
  --selection "runs\мой_выбор.json"
```

### Как посмотреть результат

Откройте папку из `--output-dir` в проводнике.

После **первой** команды (`prepare-lira-review`) там будут файлы:

- `import_summary.json` — краткая сводка: сколько строк прочитано, сколько
  принято, сколько элементов;
- `forces.json` — главный файл с усилиями, значения хранятся точно, без
  потери разрядов;
- `forces_review.csv` — та же таблица для чтения глазами, открывается в Excel;
- `blockers.json` — список причин остановки, с кодами и объяснениями;
- `mapping_snapshot.json` — снимок того, как были разобраны колонки;
- `README_REVIEW.md` — краткое описание набора.

После **второй** команды (`prepare-lira-selection`) там будут файлы:

- `manifest.json` — краткая сводка;
- `candidates.json` — все кандидаты с указанием источника каждого числа;
- `candidates.csv` — тот же список, открывается в Excel;
- `selection_template.json` — заготовка для вашего выбора расчётной строки;
- `README_SELECTION.md` — пояснение порядка работы.

**Причины остановки в `blockers.json` — это нормально.** Так работает защита от
ошибок. Каждая причина имеет код и текстовое объяснение.

## 12. Если что-то пошло не так

| Сообщение | Что означает | Что делать |
|---|---|---|
| `python : команда не найдена` | Python не установлен или не в PATH | Сообщите мне |
| `cannot find package fireprotect` | Комплекс не установлен | Сообщите мне |
| `review bundle directory already exists; refusing to overwrite` | Папка результата уже существует | Укажите другое имя папки |
| `source table is missing mapped headers` | В выгрузке другие названия колонок | Пришлите файл мне |
| `LIRA_MEMBER_PROFILE_IDENTITY_MISSING` | В выгрузке нет профиля или марки | Нужна таблица жёсткостей |
| `LIRA_LOAD_COMBINATION_IDENTITY_MISSING` | В выгрузке нет сочетаний | Нужна выгрузка по РСУ/РСН |
| `LIRA_GOVERNING_RESULT_SELECTION_UNRESOLVED` | Расчётная строка не выбрана | Это ожидаемо, см. задачу 1 |
| `Unexpected UTF-8 BOM` | Устаревшая версия | Обновите, это уже исправлено |

**Общее правило:** не пытайтесь обойти ошибку. Пришлите мне текст ошибки
целиком, и я объясню причину.
